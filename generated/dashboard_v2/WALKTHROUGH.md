### Read Function — `functions/api/clickup-sprint.ts`

Uses the **Filtered Team Tasks** endpoint (`GET /team/{team_id}/task?list_ids[]=...`), which respects multi-list memberships — that's the fix for the 2-vs-117 bug.

```typescript
// functions/api/clickup-sprint.ts
// GET /api/clickup-sprint?listId={listId}
//   → { name, totals, by_pod, data_source }
// Uses ClickUp's Filtered Team Tasks endpoint to include multi-list assignments.

interface Env {
  CLICKUP_API_TOKEN: string;
  CLICKUP_TEAM_ID: string;
}

const POD_FIELD_NAME = "Lotus Pod"; // Custom field name to group by

export const onRequestGet: PagesFunction<Env> = async ({ request, env }) => {
  const url = new URL(request.url);
  const listId = url.searchParams.get("listId");
  if (!listId) return new Response(JSON.stringify({ error: "listId required" }), { status: 400 });

  const allTasks: any[] = [];
  let page = 0;
  while (true) {
    const r = await fetch(
      `https://api.clickup.com/api/v2/team/${env.CLICKUP_TEAM_ID}/task` +
        `?list_ids[]=${listId}&include_closed=true&subtasks=true&page=${page}`,
      { headers: { Authorization: env.CLICKUP_API_TOKEN } }
    );
    if (!r.ok) {
      return new Response(JSON.stringify({ error: `ClickUp ${r.status}` }), { status: 502 });
    }
    const j = await r.json();
    const tasks = j.tasks || [];
    allTasks.push(...tasks);
    if (tasks.length < 100) break; // ClickUp returns 100/page; less = end
    page += 1;
    if (page > 20) break; // safety
  }

  // Aggregate
  const statusBucket = (s: string): string => {
    s = (s || "").toLowerCase();
    if (s.includes("complete") || s.includes("done") || s.includes("closed")) return "complete";
    if (s.includes("blocked") || s.includes("qa verify")) return "blocked";
    if (s.includes("in progress") || s.includes("in review") || s.includes("in qa")) return "in_progress";
    return "open";
  };

  const buckets = ["open", "in_progress", "complete", "blocked"];
  const totals = { total: 0, open: 0, in_progress: 0, complete: 0, blocked: 0 };
  const byPod: Record<string, any> = {};

  for (const t of allTasks) {
    const podField = (t.custom_fields || []).find((f: any) => f.name === POD_FIELD_NAME);
    let pod = "Unassigned/Cross-pod";
    if (podField && podField.value !== undefined && podField.type_config?.options) {
      const opt = podField.type_config.options.find((o: any) => o.id === podField.value || o.orderindex === podField.value);
      if (opt) pod = opt.name;
    }
    const bucket = statusBucket(t.status?.status);
    totals.total += 1;
    totals[bucket as keyof typeof totals] += 1;
    if (!byPod[pod]) byPod[pod] = { pod, total: 0, open: 0, in_progress: 0, complete: 0, blocked: 0 };
    byPod[pod].total += 1;
    byPod[pod][bucket] += 1;
  }

  return new Response(JSON.stringify({
    list_id: listId,
    totals,
    by_pod: Object.values(byPod),
    data_source: `Live from ClickUp at ${new Date().toISOString()} — ${allTasks.length} tasks`,
    fetched_at: new Date().toISOString()
  }), {
    headers: {
      "content-type": "application/json",
      "cache-control": "public, max-age=60" // edge cache 60s — keeps load on ClickUp tiny
    }
  });
};
```

**One thing to verify in setup:** the exact name of the "Lotus Pod" custom field. If it's different (e.g., "Pod" or "Team"), update `POD_FIELD_NAME` accordingly. Easy to test by hitting the endpoint and inspecting `data_source` for grouping accuracy.

### Write Function — `functions/api/save-md.ts`

```typescript
// functions/api/save-md.ts
// POST { path, content, message } → commit the change via GitHub App
import { App } from "octokit";

interface Env {
  GITHUB_APP_ID: string;
  GITHUB_INSTALLATION_ID: string;
  GITHUB_PRIVATE_KEY: string;
  GITHUB_REPO_OWNER: string;
  GITHUB_REPO_NAME: string;
  GITHUB_BRANCH: string;
}

export const onRequestPost: PagesFunction<Env> = async ({ request, env }) => {
  const { path, content, message } = await request.json() as any;

  // Guardrail: only allow writes inside planning/
  if (!path?.startsWith("planning/")) {
    return new Response(JSON.stringify({ error: "writes restricted to planning/" }), { status: 400 });
  }

  const app = new App({ appId: env.GITHUB_APP_ID, privateKey: env.GITHUB_PRIVATE_KEY });
  const octokit = await app.getInstallationOctokit(Number(env.GITHUB_INSTALLATION_ID));

  // Get current SHA so we can update in place
  let sha: string | undefined;
  try {
    const { data } = await octokit.rest.repos.getContent({
      owner: env.GITHUB_REPO_OWNER, repo: env.GITHUB_REPO_NAME,
      path, ref: env.GITHUB_BRANCH
    });
    if (!Array.isArray(data) && "sha" in data) sha = data.sha;
  } catch (e: any) {
    if (e.status !== 404) throw e;
  }

  await octokit.rest.repos.createOrUpdateFileContents({
    owner: env.GITHUB_REPO_OWNER, repo: env.GITHUB_REPO_NAME,
    path,
    message: message || `chore(picon): edit ${path}`,
    content: btoa(unescape(encodeURIComponent(content))),
    branch: env.GITHUB_BRANCH,
    sha
  });

  return new Response(JSON.stringify({ ok: true }), {
    headers: { "content-type": "application/json" }
  });
};
```

Add `octokit` as a dependency. Cloudflare Pages handles the bundling.

## Edit / Save / Cancel flow (current state)

### How it works today

1. Editable pages (Priorities, Capacity) render fields with the `.editable` class and a `data-path` attribute that encodes where the value lives in the data object (e.g. `data-path="features.2.status"` → `pod.features[2].status`).
2. Click **Edit** → `body.edit-mode` is set, fields become `contenteditable` (or `<select>` becomes enabled), Save/Cancel buttons appear, Edit hides.
3. Click **Save** → `savePathBasedEdits()` walks every `[data-path]` element, builds a sparse overlay object, writes it to `localStorage` under `lotusv2.{storageKey}` (e.g. `lotusv2.priorities.empire`).
4. On the next render the page does `deepMerge(bakedData, overlay)` so local edits show up.
5. Click **Cancel** → drops out of edit mode and re-renders from baked + existing localStorage.
6. A toast shows "Saved locally. Wire to GitHub commit per WALKTHROUGH.md."

### What's missing

The actual GitHub commit. Today's Save never touches the `.md` files in `planning/`. localStorage is per-browser, so edits aren't shared with anyone else and don't make it into the brain.

### How to wire real Save (next session)

See **"Next Session: Pages Functions (Read + Write) — Bundled Setup"** at the top of this doc. The full plan, env vars, and code for `functions/api/save-md.ts` are there.

### Round-trip serialization — deeper notes

Each editable page needs a function that takes the merged JS object and produces the equivalent markdown.

**For Priorities pages:**
- `pod.features[]` → the numbered list at the top of `planning/pods/{pod}/features.md` (preserve frontmatter and trailing notes)
- `pod.milestone_summary`, `pod.checkpoints[]` → the corresponding sections of `planning/pods/{pod}/milestone_mms.md`
- Bump the `Last Updated:` header to today's date

**For Capacity:**
- `pod_leadership[]` → the "Pod Leadership Summary" table in `planning/capacity.md`
- `disciplines[]` → discipline section tables

**Suggested order of work:**
- Start with the simplest round-trip: free-form `milestone_summary` text — write straight into the corresponding section between two HTML-comment markers. Keep the surrounding markdown intact.
- Next: Priorities `features` table — regenerate the numbered list section between markers. Highest leverage for producers.
- Capacity tables last — more rows, less frequently edited.

**Pragmatic v0** if round-trip is too fiddly: have Save produce a **PR** (not a direct commit) so a human can review the diff before merging. `octokit.rest.git.createRef` + `createCommit` + `pulls.create`.

### Optional later — "Send to agent queue" button

Ticket body includes the proposed change, target file, link back to the picon page, and the requestor. **Out of scope for the next session** — ship read+write first.

## Gotchas to remember

- **Don't access data globals via `window.X`.** The data files declare with `const`, which does NOT attach to `window` in regular `<script>` tags. Use the bare name (`PRIORITIES_DATA`, `DASHBOARD_DATA`, etc.). Bare names work because top-level `const` from one script is in scope for later scripts in the same document. If a data file fails to load, a bare reference will throw a loud `ReferenceError` — that's a feature, not a bug.
